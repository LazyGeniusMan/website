At [PT Navcore Nextology](/experience/navcore-2023) I led the Business Process Designer team: translating complex client problems into requirements the whole delivery chain could act on, guiding UI and UX work so screens matched the defined processes, and keeping the ERP integration honest.

## Requirements the team can build from

Leadership here meant writing requirements so completely that designers, developers, and testers never had to guess: operating models for marketplace and tourism clients, functional requirements for core banking and loan origination, accounting treatments and wireframes for a crowdfunding platform and a money changer point of sales.

## Low-code where it fits, scripts where it does not

Implementation combined BPMN, DMN, and REST API through low-code tools for the heavy flows, while Python scripts automated the repetitive gaps between systems. B2B tour and travel applications went through creation and rigorous test-case execution until the software provably matched the process.

## Integration is a process problem

Connecting applications to the ERP never meant mapping fields first. It meant agreeing on the process the integration enacts: who confirms what, when money moves, and what happens on failure. Field mappings fall out of those answers. Teams that start from the process ship integrations that survive the first exception; teams that start from the fields spend the project reconciling.
